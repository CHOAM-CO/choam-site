    01 · 개요 및 아키텍처

    인터랙티브 내러티브의 선택 분기는 기하급수적(2n)으로 팽창합니다. 수백 개의 조건식과 상태 전이가 게임 클라이언트 코드 곳곳에 흩어지면 인간 작성자와 AI 에이전트 모두 전체 도달 가능성을 추적할 수 없게 됩니다. 602는 분기 흐름, 타입/참조 정적 검증, 결정론적 상태 전이를 전용 런타임으로 완전히 분리하고, 게임 엔진은 오직 렌더링·연출·UI 입력·프레임 루프만 담당하도록 설계되었습니다.

    호스트 주도 실행 계약 (Host-Driven Execution Contract)

    • 숨겨진 이벤트 루프 및 백그라운드 스레드 없음: 602는 자체 틱 루프, 강제 일시정지, 백그라운드 가비지 컬렉터 스레드를 실행하지 않습니다. 모든 컴파일, 턴 진행, 상태 조회/갱신, 메모리 정리는 호스트가 명시적으로 호출한 시점에만 수행됩니다.
    • 정적 그래프 및 명목 타입 검증: 컴파일 단계(se_compile 또는 storyc check/compile)에서 미존재 턴 참조, 엔티티 상속 순환, 표현식 DAG 순환, 그룹 매개변수 isa 불일치, 타입 불일치를 실행 전에 모두 차단합니다. 컴파일이 거부되면 프로그램 핸들은 절대 발행되지 않습니다.
    • 원자적 상태 전이 및 실패 시 무변경 보장: se_session_start, se_session_advance, se_session_advance_to_yield, se_session_update가 SE_OK 이외의 상태를 반환하면 세션의 현재 단계(phase), 대기 중인 선택지 요청, 모든 상태 슬롯 값, 변경 버전(version)은 호출 직전 상태 그대로 보존됩니다.
    • 즉시 분기 복제 및 불투명 바이너리 체크포인트: se_session_clone으로 추론적 분기 탐색용 독립 세션을 즉시 복제하고, se_session_save / se_session_load로 원본 프로그램 지문과 대조 검증되는 불투명(opaque) 바이너리 바이트 버퍼 형태로 세이브 데이터를 직렬화·복원합니다.

    01 · Overview & Architecture

    Branching narratives grow exponentially (2n). Once hundreds of story predicates and state mutations are scattered across gameplay scripts, neither human writers nor AI agents can reliably audit reachability or state invariants. 602 isolates story graph topology, compile-time type/reference verification, and deterministic turn transitions inside a dedicated native runtime—leaving your game engine solely in charge of rendering, audio, UI input, and frame pacing.

    Host-Driven Execution Contract

    • Zero Hidden Event Pumps or Background Threads: 602 never spawns a background GC thread, never hooks your frame loop, and never pauses gameplay on its own. Compilation, turn stepping, state reads/updates, and bounded reclamation run strictly when your host invokes them.
    • Compile-Time Graph & Nominal Type Verification: se_compile (and storyc check / compile) statically rejects broken turn links, entity inheritance cycles, expression DAG cycles, group isa contract violations, and nominal type mismatches before runtime. Rejected definitions never publish a program handle.
    • Transactional Transitions & Failure Preservation: If se_session_start, se_session_advance, se_session_advance_to_yield, or se_session_update returns any status other than SE_OK, the session’s execution phase, pending choice request, state slot values, and mutation version remain untouched.
    • Speculative Cloning & Opaque Binary Checkpoints: Clone live sessions with se_session_clone for speculative branch previews or rollback, and persist/restore runtime state via se_session_save / se_session_load as opaque binary byte buffers verified by the engine against the originating program.

    01 · 概要とアーキテクチャ

    インタラクティブ作品の選択肢分岐は指数関数的（2n）に増大します。数百の条件分岐や状態更新がゲーム本体のコードに混在すると、人間のシナリオ担当者も AI エージェントも到達可能性や状態の整合性を把握しきれなくなります。602 は分岐フロー・型／参照の静的検証・決定論的な状態遷移を専用ネイティブランタイムへ分離し、ホスト側のゲームエンジンが描画・演出・UI 入力・フレーム制御のみに専念できる設計を採っています。

    ホスト主導の実行契約（Host-Driven Execution Contract）

    • 隠れたイベントループやバックグラウンドスレッドなし: 602 は独自の更新ループ、自動ポーズ、バックグラウンド GC スレッドを一切持ちません。コンパイル・ターン進行・状態の読み書き・メモリ回収はすべてホストが明示的に呼び出したタイミングでのみ実行されます。
    • 静的グラフ検証と公称型システム: se_compile（および storyc check / compile）が未定義ターンの参照、エンティティ継承の循環、式 DAG の循環、グループ isa 制約違反、型の不一致を実行前に検出します。検証に失敗した定義からプログラムハンドルが発行されることはありません。
    • アトミックな遷移と失敗時の状態保持: se_session_start、se_session_advance、se_session_advance_to_yield、se_session_update が SE_OK 以外を返した場合、セッションの phase、保留中の選択要求、すべての状態値、変更カウンタ（version）は呼び出し前のまま完全に保持されます。
    • セッション複製と不透明バイナリチェックポイント: se_session_clone により分岐の先読みやロールバック用の独立セッションを即座に複製でき、se_session_save / se_session_load により元のプログラムと照合検証される不透明（opaque）なバイナリバイトバッファとして状態を保存・復元できます。

    플랫폼별 직접 컴파일 명령 (C11)

    압축 해제한 아카이브 루트 디렉터리에서 호스트 바이너리를 직접 빌드하는 명령입니다. Windows에서 story_engine.dll을 동적 링크할 때는 반드시 STORY_ENGINE_USE_SHARED 전처리기 매크로를 정의해 SE_API가 __declspec(dllimport)로 확장되도록 지정해야 합니다.

    # macOS (macos-arm64 / macos-x64 — Apple Clang)
clang -std=c11 -Wall -Wextra -Werror -pedantic \
  -I./include docs/examples/quickstart.c \
  -L./lib -lstory_engine -Wl,-rpath,"$(pwd)/lib" \
  -o /tmp/quickstart

# Linux (linux-x64 — GCC / Clang)
cc -std=c11 -Wall -Wextra -Werror -pedantic \
  -I./include docs/examples/quickstart.c \
  -L./lib -lstory_engine -Wl,-rpath,"$(pwd)/lib" \
  -o /tmp/quickstart

# Windows (windows-x64 — MSVC cl.exe, x64 Native Tools Prompt)
cl /std:c11 /W4 /DSTORY_ENGINE_USE_SHARED /I"include" ^
  docs\examples\quickstart.c ^
  /link /LIBPATH:"lib" story_engine_import.lib /OUT:quickstart.exe

# Windows (windows-x64 — LLVM clang-cl.exe)
clang-cl /std:c11 /W4 /DSTORY_ENGINE_USE_SHARED /I"include" ^
  docs\examples\quickstart.c lib\story_engine_import.lib /Fe:quickstart.exe

    CMake SHARED IMPORTED 타깃 연동

    -DSTORY_ENGINE_PACKAGE=/abs/path/to/story-engine-v1.1.0-<platform>를 받아 플랫폼별 공유 라이브러리와 헤더, Windows STORY_ENGINE_USE_SHARED 매크로를 깔끔하게 캡슐화하는 CMakeLists.txt 구성입니다.

set_target_properties(story_engine PROPERTIES
  INTERFACE_INCLUDE_DIRECTORIES "${STORY_ENGINE_PACKAGE}/include"
)

if(WIN32)
  set_target_properties(story_engine PROPERTIES
    IMPORTED_LOCATION "${STORY_ENGINE_PACKAGE}/bin/story_engine.dll"
    IMPORTED_IMPLIB   "${STORY_ENGINE_PACKAGE}/lib/story_engine_import.lib"
    INTERFACE_COMPILE_DEFINITIONS "STORY_ENGINE_USE_SHARED"
  )
elseif(APPLE)
  set_target_properties(story_engine PROPERTIES
    IMPORTED_LOCATION "${STORY_ENGINE_PACKAGE}/lib/libstory_engine.dylib"
  )
else()
  set_target_properties(story_engine PROPERTIES
    IMPORTED_LOCATION "${STORY_ENGINE_PACKAGE}/lib/libstory_engine.so"
  )
endif()

add_executable(game_host src/main.c)
target_link_libraries(game_host PRIVATE story_engine)

    미서명 바이너리 실행 유의사항: 현재 배포 바이너리에는 Apple 공증(notarization) 및 Windows Authenticode 상용 코드 서명이 적용되어 있지 않습니다. 반드시 공식 출처(choam.studio 또는 CHOAM-CO/602-releases) 및 SHA-256 해시를 먼저 확인한 뒤 아래 절차를 적용하십시오.

    • macOS Gatekeeper 격리 해제: 압축 해제 폴더에서 xattr -dr com.apple.quarantine ./story-engine-v1.1.0-macos-arm64 (또는 story-editor-v0.1.1-macos-arm64) 실행
    • Windows SmartScreen 및 DLL 경로: 출처 확인 후 추가 정보 → 실행 선택. 호스트 실행 시 bin\story_engine.dll을 실행 파일 옆에 복사하거나 PATH에 bin 폴더를 추가하십시오.
    • Linux 실행 권한: 파일 권한이 유실된 경우 chmod +x ./bin/storyc (에디터는 chmod +x ./story-editor ./agent/story-agent) 실행

    #include "story_engine/story_engine.h"
#include <stdio.h>

static void print_and_release(se_buffer *buf) {
    if (buf->data) {
        fwrite(buf->data, 1, buf->size, stdout);
        fputc('\n', stdout);
    }
    se_buffer_release(buf);
}

int main(void) {
    if (se_abi_version() != 1u) return 1;

    const char *source_json =
        "{\"format\":\"story-engine/turn-source/1\","
        "\"types\":[{\"id\":\"Coins\",\"value_type\":\"int\"}],"
        "\"entities\":[{\"id\":\"clerk\"}],"
        "\"states\":[{\"id\":\"coins\",\"owner\":\"clerk\",\"declared_type\":\"Coins\",\"initial\":50}],"
        "\"turns\":["
        "{\"id\":\"open\",\"kind\":\"update\",\"updates\":[{\"target\":\"coins\",\"op\":\"subtract\",\"value\":10}],\"next\":\"greet\"},"
        "{\"id\":\"greet\",\"kind\":\"dialogue\",\"actor\":\"clerk\",\"text\":\"Pass issued.\",\"next\":\"done\"},"
        "{\"id\":\"done\",\"kind\":\"end\"}"
        "]}";

    se_program program = 0;
    se_session session = 0;
    se_buffer out = {0};
    int rc = 1;

    if (se_compile(source_json, &program, &out) != SE_OK) {
        print_and_release(&out);
        goto cleanup;
    }
    se_buffer_release(&out);

    if (se_session_create(program, 42ULL, &session, &out) != SE_OK) goto cleanup;
    se_buffer_release(&out);

    if (se_session_start(session, "{\"turn\":\"open\"}", &out) != SE_OK) goto cleanup;
    se_buffer_release(&out);

    /* 내부 update("open")를 거친 뒤 첫 가시 턴("greet")과 누적 changes를 반환 */
    if (se_session_advance_to_yield(session, NULL, 16, &out) != SE_OK) goto cleanup;
    print_and_release(&out);

    /* 종료 턴("done") 실행 -> phase == "ended" */
    if (se_session_advance_to_yield(session, NULL, 16, &out) != SE_OK) goto cleanup;
    print_and_release(&out);
    rc = 0;

cleanup:
    se_buffer_release(&out);
    if (session != 0) se_session_release(session);
    if (program != 0) se_program_release(program);
    return rc;
}

        "\"turns\":["
        "{\"id\":\"open\",\"kind\":\"update\",\"updates\":[{\"target\":\"coins\",\"op\":\"subtract\",\"value\":10}],\"next\":\"greet\"},"
        "{\"id\":\"greet\",\"kind\":\"dialogue\",\"actor\":\"clerk\",\"text\":\"Pass issued.\",\"next\":\"done\"},"
        "{\"id\":\"done\",\"kind\":\"end\"}"
        "]}";

    se_program program = 0;
    se_session session = 0;
    se_buffer out = {0};
    int rc = 1;

    if (se_compile(source_json, &program, &out) != SE_OK) {
        print_and_release(&out);
        goto cleanup;
    }
    se_buffer_release(&out);

    if (se_session_create(program, 42ULL, &session, &out) != SE_OK) goto cleanup;
    se_buffer_release(&out);

    if (se_session_start(session, "{\"turn\":\"open\"}", &out) != SE_OK) goto cleanup;
    se_buffer_release(&out);

    /* 内部 update ("open") を通過し、可視ターン ("greet") と累積 changes を取得 */
    if (se_session_advance_to_yield(session, NULL, 16, &out) != SE_OK) goto cleanup;
    print_and_release(&out);

    /* 終了ターン ("done") を実行 -> phase == "ended" */
    if (se_session_advance_to_yield(session, NULL, 16, &out) != SE_OK) goto cleanup;
    print_and_release(&out);
    rc = 0;

cleanup:
    se_buffer_release(&out);
    if (session != 0) se_session_release(session);
    if (program != 0) se_program_release(program);
    return rc;
}

    "capture"id, kind, snapshot, nextname指定スナップショットの不変レコード（"<snapshot>#N"）を生成します（ペイロード不可）。
    "end"id, kindname, payload/payload_exprストーリーを終了し、セッションを "ended" に遷移させます。
    • 4 種類のルート（Route）: ① 単一ターン遷移（"greet" または {"turn":"window","use":"b_visit"}）、② 条件分岐（{"if":"bool_expr","then":...,"else":...}）、③ シード乱数による重み付き抽選（{"weighted":[{"when":"...","weight":"...","next":...}]}）、④ グループ出口（{"exit":"bought"}）。
    • 構造化ペイロード（payload / payload_expr）: 可視ターン（dialogue, action, choice, end）および choices[] の各項目に "payload": {"declared_type": "Cue", "value": ...} または "payload_expr": "cue_expr_id"（排他指定）を付与し、カメラ演出や音声キー等の型付きメタデータを渡せます。

    • 해제 의무 및 멱등성: 성공 여부와 무관하게 out.data != NULL이면 사용 후 반드시 se_buffer_release(&out)로 해제하십시오(호출자의 free() 사용 금지, 구조체 값 복사로 중복 해제 금지). 해제된 구조체는 자동으로 {0}으로 리셋됩니다.
    • 텍스트 JSON vs 불투명 바이너리 출력: JSON 출력 함수는 편의를 위해 data[size]에 여분의 '\0'을 덧붙이지만(size는 종단 NUL 제외), se_program_artifact와 se_session_save가 반환하는 불투명 바이너리 버퍼는 내부에 0x00 바이트를 포함할 수 있으므로 strlen을 쓰지 말고 정확히 size 바이트만 처리하십시오.

    • Zero-Initialize Output Buffers: Every output se_buffer must be initialized to {0} before a call. Passing a non-empty buffer (data != NULL or size != 0) returns SE_INVALID_ARGUMENT without overwriting existing data.

    • 出力バッファの {0} 初期化: 出力用の se_buffer は呼び出し前に必ず {0} で初期化してください。空でないバッファを渡すと既存データを破壊せず即座に SE_INVALID_ARGUMENT を返します。
    • se_buffer_release による解放: 成功・失敗にかかわらず buf.data != NULL の場合は se_buffer_release(&buf) で解放してください（free() の直接呼び出しや構造体の浅いコピーによる二重解放は禁止）。解放後は {0} にリセットされます。
    • JSON 出力と不透明バイナリ出力の扱い: JSON 出力は data[size] に終端 '\0' が付与されます（size は終端を除く）。一方、se_program_artifact と se_session_save の出力は途中に 0x00 を含み得る不透明バイナリであるため、必ず size バイト数で処理してください。
    • ハンドル寿命とスレッド安全性: se_program・se_session・se_object は 0 以外の uint64_t であり再利用されません。C ABI 経由の並行呼び出しは内部で直列化されますが、呼び出し中の入力メモリおよび出力 se_buffer を別スレッドから変更・解放してはなりません。

    completed_choicestring選択応答を完了した呼び出しでは対象選択ターンの ID、それ以外は ""。
    next / exitstring次回実行予定のターン ID、およびグループ出口から "idle" に戻った際の出口名。

    プログラム検査・状態操作・不透明バイナリ契約

    • se_program_inspect: format, name, fingerprint, default_state_access, types, entities（parents・ancestors 含む）, states（inherited・inherited_from 含む）, snapshots, groups, uses, turns（has_payload 含む）を返します。
    • se_session_read / se_session_update / se_session_evaluate:
      • se_session_read(s, "[\"coins\"]", &out) → {"ok":true,"result":{"coins":{"kind":"int","value":"40"}}}
      • se_session_update(s, "[{\"target\":\"coins\",\"op\":\"add\",\"value\":10}]", NULL, &out) → [{"state","before","after"}] を返却（readonly_state や pending_choice、型エラー時はバッチ全体をロールバック）。
      • se_session_evaluate(s, "effective_fee", NULL, &out) → {"ok":true,"result":{"value":{...},"declared_type":""}}
    • 不透明バイナリアーティファクトとチェックポイント: se_program_artifact / se_program_load のアーティファクトおよび se_session_save / se_session_load のチェックポイントは、内部構造が非公開の不透明（opaque）なバイナリバイトバッファ（data + size）です。バイト列を解析・改変せず必ず size バイト全体をそのまま保存・受け渡ししてください。ロード時にエンジンが元のプログラムとの整合性を検証し、不正データや別プログラムのチェックポイントは invalid_artifact・invalid_checkpoint・incompatible_program で拒否します。

    Subcommand Stream & File Behavior

    Subcommand stdout / stderr Contract Execution & File Semantics
    check <source.json> Prints a single-line JSON diagnostic array to stdout ([] when clean). File I/O or JSON syntax/schema decode errors emit {"ok":false,"error":...} to stderr. Runs full static validation without writing an artifact. Warnings alone still exit with code 0.

Recoverable runtime rejections (such as an invalid option ID) print an error JSON line to stdout and continue awaiting valid input.

    08 · C++ / C# (Unity) / Godot 엔진 연동

    모든 호스트 언어 어댑터는 동일한 C ABI(story_engine.h) 위에서 동작하며, 다음 4가지 공통 원칙을 따릅니다: ① 길이 기반 문자열의 내부 NUL 바이트 사전 차단(embedded_nul), ② 64비트 핸들의 명시적 소유권 해제(RAII / IDisposable / RefCounted), ③ 64비트 십진 문자열 정수 파싱, ④ 프레임 여유 시점에 호스트가 직접 호출하는 collect / collect_retired.

    1. C++17 & Unreal Engine

    C++17 호스트에서는 se_program, se_session, se_object, se_buffer를 이동 전용(Move-only) RAII 래퍼로 감싸 예외 안전성을 확보합니다. Unreal Engine 플러그인 모듈에서는 ThirdParty/StoryEngine/include/story_engine와 플랫폼별 라이브러리(Mac, Linux, Win64)를 Build.cs에 등록하며, 스토리 상태를 UObject GC에 종속시키지 않고 게임 서브시스템/컴포넌트 멤버 수명으로 관리합니다.

    // C++17 RAII 패턴 예시 (story_engine.h 직접 래핑)
auto prog = story_engine::binding::Program::load(artifact_bytes.data(), artifact_bytes.size());
auto sess = prog.session(/*seed=*/42);
sess.start(R"({"turn":"record_opening"})");

// 내부 update/capture를 통과해 첫 가시 턴까지 진행
auto step_buf = sess.advance_to_yield(nullptr, /*max_steps=*/64);
std::string step_json = step_buf.text();

// 추론적 분기 미리보기용 O(1) 복제 및 불투명 체크포인트 저장
auto preview = sess.clone();
auto saved_checkpoint = sess.save(); // saved_checkpoint.data(), saved_checkpoint.size()

    2. Unity 및 매니지드 C# (P/Invoke + SafeHandle)

    Unity 및 .NET 호스트에서는 네이티브 바이너리(libstory_engine.dylib, libstory_engine.so, story_engine.dll)를 네이티브 플러그인 경로에 배치하고 CallingConvention.Cdecl로 P/Invoke합니다. 32비트 호스트에서도 핸들이 잘리지 않도록 네이티브 핸들은 IntPtr 대신 항상 ulong으로 유지하며, SafeHandle(DangerousAddRef / DangerousRelease)과 IDisposable을 함께 구현해 활성 호출 중 동시 Dispose 경쟁을 방지합니다.

    using StoryEngine;

using var program = Program.Load(artifactBytes);

using (session.Start("{\"turn\":\"record_opening\"}")) { }

using (Result step = session.AdvanceToYield(answer: null, maxSteps: 64))
{

    // 선택 대기 시: session.AdvanceToYield("{\"request\":\"choice#1\",\"option\":\"pay\"}", 64)
}

// 씬 전환 등 호스트가 선택한 시점에 은퇴 세션 정리
using (Result gc = Collector.CollectRetired(budget: 128)) { }

    08 · C++ / C# (Unity) / Godot Integration

    All host language adapters layer cleanly atop the same C11 ABI (story_engine.h) and enforce four shared invariants: (1) reject embedded NUL bytes in length-aware host strings before crossing into C strings (embedded_nul), (2) manage 64-bit handles deterministically (RAII, IDisposable, or RefCounted), (3) parse canonical 64-bit integers from decimal strings, and (4) invoke collect / collect_retired explicitly at host-chosen frame boundaries.

    1. C++17 & Unreal Engine

    Wrap se_program, se_session, se_object, and se_buffer in move-only C++17 RAII owners. Store RAII owners inside subsystem or component members rather than wrapping individual story states as UObject instances.

    # 1) 초기 관리자 계정 생성 (24시간 유효 임시 비밀번호 발급, 첫 로그인 시 /change-password 필수)

# 2) 루프백 백엔드 기동 (외부 공개 HTTPS 오리진 필수)

  --public-url https://story.example \
  --account-database /var/lib/story-editor/auth.sqlite3 \
  --database /var/lib/story-editor/editor.sqlite3 \
  --host 127.0.0.1 \
  --port 8781 \
  --trust-https-proxy
    # Caddyfile 예시 (Host 및 X-Forwarded-Proto 자동 전달 + 즉시 스트림 플러시)
story.example {
    reverse_proxy 127.0.0.1:8781
}

# Nginx 핵심 location 설정 (Host 유지 및 에이전트 NDJSON 스트리밍 버퍼링 해제 필수)

    proxy_pass http://127.0.0.1:8781;
    proxy_http_version 1.1;

    Release Highlights

    • 602 Story Engine SDK v1.1.0 (C ABI v1 / story-engine/turn-source/1):
      • Session cloning (se_session_clone) and opaque binary session checkpoints (se_session_save, se_session_load, up to 16 MiB) verified by the engine against the originating program.
      • State mutability control via default_state_access and states[].access ("external" | "internal", rejecting external host writes with readonly_state).
      • Compile-time entity state slot inheritance (entities[].parents) and subtype checking on group entity parameters (isa).
      • Type-checked structured payload / payload_expr attachments on observable turns and choice options.
      • Bounded multi-turn stepping (se_session_advance_to_yield, step_budget_exceeded), program catalog inspection (se_program_inspect), and unified ok: false envelopes on SE_COMPILE_ERROR.
    • 602 Story Editor v0.1.1:
      • Bundles Story Engine v1.1.0 native shared libraries and story_engine.h.
      • Self-contained story-editor server and agent/story-agent binaries across linux-x64, windows-x64, and macos-arm64 with zero host Python/Node.js setup.
      • Visual turn/group graph workspace, arbitrary-turn scene jump simulator, and Remote MCP (POST /mcp, 2026-07-28 & 2025-11-25) guarded by 6-hex optimistic concurrency hashes.

    Platform & Operational Caveats

    • Platform Matrix: Story Engine SDK ships for 4 platforms (including macos-x64), whereas Story Editor v0.1.1 ships for 3 platforms (linux-x64, windows-x64, macos-arm64).
    • Code Signing & HTTPS Proxy: Binaries are currently unsigned / ad-hoc signed without Apple notarization or Windows Authenticode; story-editor serve requires a TLS-terminating HTTPS reverse proxy in front of its loopback listener.
    • Windows External AI Provider Auth: On Windows, configure external LLM providers with STORY_AGENT_PROVIDER=openai and STORY_AGENT_API_KEY (OAuth --login is POSIX-only; core editing, native compilation, simulation, and Remote MCP require no AI credentials).
