    01 · 개요 및 아키텍처

    인터랙티브 내러티브의 선택 분기는 기하급수적(2n)으로 팽창합니다. 수백 개의 조건식과 상태 전이가 게임 클라이언트 코드 곳곳에 흩어지면 인간 작가와 AI 에이전트 모두 전체 도달 가능성을 추적할 수 없게 됩니다. 602 v2.0.0은 작가가 순수 텍스트 마크다운(.md) 폴더로 집필하고, C11 네이티브 엔진(story_engine_v2.h)이 파싱·정적 진단·결정론적 시뮬레이션·역방향 도달 추적(Backward Reachability)을 일관되게 수행하는 로컬 중심 아키텍처입니다.

    핵심 아키텍처 원칙

    • 순수 로컬 마크다운 원고 폴더 (Git 친화적 집필): 원고는 project.json, 전역 선언 파일 declarations.md, 장면별 마크다운 events/*.md, 다국어 번역 translations.json으로 구성된 일반 폴더에 저장됩니다. 원격 서버나 데이터베이스 설정 없이 즉시 집필하고 Git으로 버전 관리할 수 있습니다.
    • 호스트 주도 결정론적 실행 (Host-Driven Execution): 602 Story Engine은 백그라운드 스레드나 자체 틱 루프를 실행하지 않습니다. 모든 마크다운 분석(story_v2_analyze), 1턴 시뮬레이션 실행(story_v2_simulate / story_v2_execute_play), 정적 진단(story_v2_check), 역방향 도달 경로 산출(story_v2_reach)은 호스트가 호출한 시점에만 결정론적으로 수행됩니다.
    • 에디터–런타임 100% 단일 진실 공급원 (Single Source of Truth): 602 Studio 데스크톱 앱과 게임 클라이언트에 임베딩되는 네이티브 라이브러리가 동일한 C11 엔진 코어를 공유합니다. 스튜디오의 1턴 플레이어에서 검증한 분기·인터럽트·계약 결과가 실제 게임 빌드(.602.json 런타임 번들)에서 바이트 단위로 동일하게 작동합니다.
    • 충돌 없는 AI 에이전트 협업 (Hashline + Base Revision): 줄 내용 기반 2글자 체크섬 hashline(예: 14#K2)과 파일 리비전 해시(base_revision)를 결합해, 인간 작가와 로컬 MCP 에이전트(Claude Desktop, Claude Code, Cursor, Codex 등)가 동시에 원고를 다듬어도 줄 밀림(line drift)이나 덮어쓰기 사고를 원천 차단합니다.

    01 · Overview & Architecture

    Branching choices in interactive narratives grow exponentially (2n). When hundreds of conditions and state mutations are scattered across game client scripts, neither human writers nor AI agents can reason about full reachability. 602 v2.0.0 is a local-first architecture where writers author plain-text Markdown (.md) folders while a deterministic C11 native engine (story_engine_v2.h) handles parsing, static diagnostics, turn simulation, and backward reachability analysis.

    Core Architectural Principles

    • Local Markdown Manuscript Folders (Git-Native Authoring): Manuscripts live in plain folders consisting of project.json, global declarations in declarations.md, scene files in events/*.md, and localization tables in translations.json. Zero database or remote server setup is required.
    • Host-Driven Deterministic Execution: 602 Story Engine spawns no background threads or hidden tick loops. Every Markdown parse (story_v2_analyze), turn simulation (story_v2_simulate / story_v2_execute_play), static diagnostic check (story_v2_check), and backward reachability query (story_v2_reach) executes deterministically only when invoked by the host.
    • Single Source of Truth Across Editor & Runtime: 602 Studio and the embeddable native library share the exact same C11 engine core. Every branch, interrupt, and contract verified in the Studio 1-turn player behaves identically in shipping game builds consuming compiled .602.json runtime bundles.
    • Collision-Free AI Agent Collaboration (Hashline + Base Revision): Combining 2-character content checksums per line (hashline, e.g., 14#K2) with file-level revision hashes (base_revision) prevents line-drift corruption and stale overwrites when writers and local MCP agents (Claude Desktop, Claude Code, Cursor, Codex) edit manuscripts concurrently.

    01 · 概要とアーキテクチャ

    インタラクティブ・ナラティブの選択分岐は指数関数的（2n）に膨張します。数百の条件式と状態遷移がゲームクライアントのコード各所に散在すると、人間の作家も AI エージェントも到達可能性の全体像を追跡できなくなります。602 v2.0.0 は、プレーンテキストの Markdown（.md）フォルダで原稿を執筆し、決定論的な C11 ネイティブエンジン（story_engine_v2.h）がパース・静的診断・ターンシミュレーション・逆方向到達可能性解析（Backward Reachability）を一貫して担うローカルファースト・アーキテクチャです。

    コア・アーキテクチャ原則

    • ローカル Markdown 原稿フォルダ（Git 親和性の高い執筆）: 原稿は project.json、グローバル宣言 declarations.md、シーン別ファイル events/*.md、多言語翻訳 translations.json から成る通常のフォルダに保存されます。データベースやリモートサーバーの構築なしで即座に執筆・Git 管理が可能です。
    • ホスト主導の決定論的実行（Host-Driven Execution）: 602 Story Engine はバックグラウンドスレッドや独自のティックループを持ちません。Markdown 解析（story_v2_analyze）、1 ターンシミュレーション（story_v2_simulate / story_v2_execute_play）、静的診断（story_v2_check）、逆方向到達パス算出（story_v2_reach）はすべてホストが呼び出した時点でのみ決定論的に実行されます。
    • エディタとランタイムの完全な単一真実源（Single Source of Truth）: 602 Studio デスクトップアプリとゲームクライアントに組み込まれるネイティブライブラリは同一の C11 エンジンコアを共有します。Studio の 1 ターンプレイヤーで検証した分岐・割り込み・契約結果は、実ゲームビルド（.602.json ランタイムバンドル）でも完全に同一に動作します。
    • 衝突のない AI エージェント協調（Hashline + Base Revision）: 行内容に基づく 2 文字チェックサム hashline（例：14#K2）とファイルリビジョンハッシュ（base_revision）を組み合わせ、作家とローカル MCP エージェント（Claude Desktop、Claude Code、Cursor、Codex 等）が同時に編集しても行ズレ（line drift）や上書き競合を防止します。

# Windows (x86_64 PowerShell) 무결성 검증 및 설치 프로그램 실행

    1) 전역 선언 파일 (declarations.md) 문법

    문법 / 디렉티브 용도 작성 예시
    \화자이름

    \유진: 등대지기

    /set has_key = false
    /persist 변수명 = 초기값 회차·세이브/로드를 초월해 유지되는 영속(메타) 변수 선언. /restore 호출 시에도 덮어써지지 않고 현재 값을 유지함 /persist loop_count = 0
    /persist true_hint_seen = false
    /contract 계약명
    /with 입력변수 = 기본값
    /result 결과변수 = 기본값    		 전투, 상점, 미니게임 등 호스트 게임 시스템과 주고받는 입출력 계약(External Contract) 선언 /contract LockpickMiniGame
    /with difficulty = 2
    /result unlocked = false
    /interrupt 인터럽트명
    /when 조건식
    -> 대상장면 (또는 /goto)    		 매 턴 진행 중 조건식이 참이 되면 즉시 개입하는 전역 인터럽트 규칙 선언 /interrupt GameOverCheck
    /when hp <= 0
    /goto dead_end

    2) 장면 원고 파일 (events/*.md) 문법

    문법 / 디렉티브 용도 작성 예시

    /when 조건식 장면 진입 가능 조건 또는 인터럽트 발동 조건 /when hp > 0 and not is_locked
    /enter / /exit 장면 진입 직후(/enter) 및 장면 이탈 직전(/exit)에 자동 실행할 /set·/persist 상태 변경 훅 /enter
    /set visited_lighthouse = true
    \화자: 대사 내용
    또는 일반 문단    		 화자 지정 대사(\화자: ...) 및 내레이션 산문 문단 \유진: 오늘 밤 파도가 심상치 않군.
    차가운 바닷바람이 옷깃을 스쳤다.
    // 작성자 메모 작가 전용 주석. 에디터에서는 배지로 표시되며, .602.json 런타임 번들 컴파일 시 완전히 제거됨 // TODO: 2회차 힌트 대사 보강
    /if 조건식
    /elif 조건식
    /else    		 4칸 들여쓰기 기반 조건부 대사·상태 변경·전이 블록 /if loop_count >= 1
    \유진: …이 장면, 전에도 본 적이 있어.
    - [조건식] 선택지 텍스트
    - 선택지 텍스트    		 플레이어 선택지 그룹. 조건식을 생략하면 [true]로 간주하며, 4칸 들여쓰기로 하위 대사·상태 변경·하위 선택지 트리를 무제한 중첩 가능 - [has_key] 철문을 연다
    \유진: 자물쇠가 풀렸다.
    -> 등대_내부
    -> 대상장면
    /goto 대상장면
    /return    		 ->는 대상 장면을 호출(인터럽트/서브장면 복귀 지점 유지 후 전이), /goto는 호출 스택을 비우고 즉시 점프, /return은 인터럽트/호출 이전 지점으로 복귀 -> 상점_이벤트
    /goto 엔딩_크레딧
    /return
    /save / /restore 원고 흐름 안에서 현재 일반 상태(/set) 스냅샷을 저장(/save)하거나 마지막 저장 지점으로 복원(/restore, 단 /persist 변수는 유지) /save
    /restore
    /game 계약명
    /with 입력 = 식
    /result 변수 = 결과필드    		 선언된 외부 게임 시스템 계약(/contract)을 호출하고 결과값을 원고 상태 변수에 바인딩 /game LockpickMiniGame

    3) Static Diagnostic Codes (story_v2_check)

    Diagnostic Code Severity Condition & Resolution
    DEAD_END_CHOICE_GROUP Warning / Error Every option in a choice group has a guard condition ([cond]) without an unconditional fallback (- [true] ...), risking zero available choices at runtime.
    UNREACHABLE_EVENT Warning An event cannot be reached from entry_event or any /interrupt rule via -> or /goto transitions.
    INTERRUPT_LEAK Error An interrupt target scene fails to terminate with /return or an explicit terminal /goto, risking call-stack leakage or infinite re-entry.
    MISSING_TRANSLATION Warning A dialogue or choice line lacks a translation entry for one or more languages configured in project.json.
    STALE_TRANSLATION Warning The source line was edited (changing its content hash), leaving an outdated translation entry that needs review in Studio's 1:1 translation view.

    診断コード 重要度 検出条件と対処方法

    story_engine_v2.h의 모든 진입점은 불투명 구조체 포인터나 콜백 테이블 없이 표준 C 문자열(const char* -> char*)만 주고받으므로 C++17(Unreal/자체 엔진), Unity C# P/Invoke, Godot GDExtension/C# 등 모든 환경에서 수십 줄의 래퍼만으로 즉시 연동됩니다.

    1) C++17 RAII 래퍼 예제

    #include "story_engine_v2.h"
#include <memory>
#include <string>

namespace story602 {

struct GroupBDeleter {
    void operator()(char *p) const noexcept {
        if (p) story_v2_free(p);
    }
};

struct GroupADeleter {
    void operator()(char *p) const noexcept {
        if (p) story_v2_free_string(p);
    }
};

inline std::string simulate(
    const std::string &declarations_md,
    const std::string &events_md,
    const std::string &options_json
) {
    std::unique_ptr<char, GroupBDeleter> raw(
        story_v2_simulate(declarations_md.c_str(), events_md.c_str(), options_json.c_str())
    );
    return raw ? std::string(raw.get()) : "{}";
}

inline std::string execute_play(
    const std::string &bundle_json,
    const std::string &play_request_json
) {
    std::unique_ptr<char, GroupADeleter> raw(
        story_v2_execute_play(bundle_json.c_str(), play_request_json.c_str())
    );
    return raw ? std::string(raw.get()) : "{}";
}

} // namespace story602

    2) Unity C# P/Invoke 연동 예제

    libstory_engine.dylib(macOS), story_engine_v2.dll(Windows) 또는 libstory_engine.so(Linux)를 Assets/Plugins/에 배치하고 UTF-8 포인터 마샬링으로 호출합니다.

    using System;
using System.Runtime.InteropServices;
using System.Text;

public static class StoryEngineV2
{
    private const string LibName = "story_engine";

    [DllImport(LibName, CallingConvention = CallingConvention.Cdecl)]
    private static extern IntPtr story_v2_simulate(byte[] declarationsMd, byte[] eventsMd, byte[] optionsJson);

    [DllImport(LibName, CallingConvention = CallingConvention.Cdecl)]
    private static extern void story_v2_free(IntPtr ptr);

    [DllImport(LibName, CallingConvention = CallingConvention.Cdecl)]
    private static extern IntPtr story_v2_execute_play(byte[] projectJson, byte[] playRequestJson);

    [DllImport(LibName, CallingConvention = CallingConvention.Cdecl)]
    private static extern void story_v2_free_string(IntPtr ptr);

    private static byte[] ToUtf8NullTerminated(string s)
    {
        int len = Encoding.UTF8.GetByteCount(s);
        byte[] buf = new byte[len + 1];
        Encoding.UTF8.GetBytes(s, 0, s.Length, buf, 0);
        return buf;
    }

    public static string Simulate(string declarationsMd, string eventsMd, string optionsJson)
    {
        IntPtr ptr = story_v2_simulate(
            ToUtf8NullTerminated(declarationsMd),
            ToUtf8NullTerminated(eventsMd),
            ToUtf8NullTerminated(optionsJson)
        );
        if (ptr == IntPtr.Zero) return "{}";
        try {
            return Marshal.PtrToStringUTF8(ptr) ?? "{}";
        } finally {
            story_v2_free(ptr);
        }
    }

    public static string ExecutePlay(string bundleJson, string playRequestJson)
    {
        IntPtr ptr = story_v2_execute_play(
            ToUtf8NullTerminated(bundleJson),
            ToUtf8NullTerminated(playRequestJson)
        );
        if (ptr == IntPtr.Zero) return "{}";
        try {
            return Marshal.PtrToStringUTF8(ptr) ?? "{}";
        } finally {
            story_v2_free_string(ptr);
        }
    }
}

    list_projects workspace_dir（任意） 開いているプロジェクトまたは指定ディレクトリ内の 602 原稿プロジェクト一覧、開始イベント、ファイル構成を取得します。
    open_project_folder project_path ローカル原稿フォルダ（または .602.zip）をワークスペースにロードし、メタデータと初期リビジョン情報を返します。
    save_project_folder project_path, export_zip（任意） メモリ上の原稿変更をディスク上のフォルダ（および任意の .602.zip アーカイブ）へ原子的に保存します。
    read_manuscript target（declarations.md または events/<id>.md） 対象原稿ファイルの現在の revision ハッシュと、各行の先頭に 2 文字チェックサムタグが付与された hashline テキスト（例：14#K2: \ユジン: 扉が固く閉ざされている。）を返します。
    edit_manuscript target, base_revision, edits（start_anchor, end_anchor, replacement） base_revision と行アンカーチェックサム（14#K2）を照合した上で指定行範囲を原子的に置換します。不一致時は編集を拒否し、行ズレ（line drift）事故を防止します。
    simulate_manuscript start_event, choices, initial_state, contract_results 現在の原稿に対して story_v2_simulate および逆方向到達解析（story_v2_reach）を実行し、ターン進行結果と状態遷移を検証します。
    check_manuscript include_translations（任意） プロジェクト全体に対して story_v2_check 静的診断を実行し、行き止まり選択肢、孤立シーン、割り込みリーク、翻訳漏れ／陳腐化の一覧を返します。
    compile_manuscript output_path 静的検証の通過後、執筆メモ（//）を除去した配布用 .602.json ランタイムバンドルを生成し、source_hash を返します。
